# 架构与接口

> 这份文档是各模块之间的约定。接口签名一旦合入主分支，修改必须先在组内说明，并由组长更新本文档。

## 一、分层

```
界面 ui  ──调用──▶  业务 services  ──调用──▶  数据 repository  ──▶  SQLite
   │                    │                        │
   └────────────── 都使用 models 中的数据类 ───────┘
```

| 层 | 职责 | 规则 |
|---|---|---|
| `models` | 描述数据长什么样 | 只有字段，没有业务逻辑 |
| `services` | 业务规则：校验、计费、统计、预警、出入流程 | 不导入 PySide6；不直接写 SQL |
| `repository` | 把数据存进数据库、取出来 | 只做读写，不做业务判断 |
| `ui` | 显示数据、接收操作 | 不写 SQL；不写计费和统计公式 |

**为什么这样分**：计费、统计这类规则最容易出错，也最需要测试。把它们写成不依赖界面和数据库的函数，就可以直接用数据验证，不必每次打开程序手工点。详见决策记录 ADR-003。

依赖方向只能从上往下：`ui` 可以调用 `services`，`services` 可以调用 `repository`，反过来不行。

## 三、数据类（`app/models/entities.py`）

```python
from dataclasses import dataclass
from datetime import date, datetime

@dataclass
class User:
    id: int | None
    username: str
    password_hash: str
    role: str                      # "admin" 管理员 / "guard" 门卫

@dataclass
class Resident:
    id: int | None
    name: str
    building: str                  # 楼栋，如 "3号楼"
    room: str                      # 房号，如 "2-501"
    phone: str

@dataclass
class Vehicle:
    id: int | None
    plate: str                     # 车牌号，唯一
    vehicle_type: str              # "monthly" 月租 / "temp" 临时 / "visitor" 访客
    resident_id: int | None        # 月租车必填；访客车填被访住户；临时车为空
    monthly_expire: date | None    # 月租到期日，仅月租车有
    note: str = ""

@dataclass
class ParkingSpace:
    id: int | None
    code: str                      # 车位编号，唯一，如 "A-012"
    zone: str                      # 区域，如 "A区"
    status: str                    # "free" 空闲 / "occupied" 占用 / "reserved" 预约
    fixed_vehicle_id: int | None   # 固定车位绑定的月租车，可空

@dataclass
class ParkingRecord:
    id: int | None
    plate: str
    vehicle_type: str              # 入场时的车辆类型，之后不随车辆资料变化
    enter_time: datetime
    exit_time: datetime | None     # 为空表示仍在场
    fee: int | None                # 应收金额（元），出场时写入
    space_id: int | None
    operator: str                  # 操作员用户名

@dataclass
class FeeRule:
    vehicle_type: str              # "temp" / "visitor"
    free_minutes: int
    hourly_rate: int               # 元
    daily_cap: int                 # 每 24 小时封顶，元

@dataclass
class Reservation:
    id: int | None
    space_id: int
    plate: str
    start_time: datetime
    end_time: datetime
```

类型常量（`"monthly"` 等）统一定义在 `entities.py` 顶部，其他文件导入使用，不要手写字符串：

| 用途 | 常量 | 值 | 全部取值的元组 |
|---|---|---|---|
| 用户角色 | `ROLE_ADMIN`、`ROLE_GUARD` | `"admin"`、`"guard"` | `ROLES` |
| 车辆类型 | `VEHICLE_MONTHLY`、`VEHICLE_TEMP`、`VEHICLE_VISITOR` | `"monthly"`、`"temp"`、`"visitor"` | `VEHICLE_TYPES` |
| 车位状态 | `SPACE_FREE`、`SPACE_OCCUPIED`、`SPACE_RESERVED` | `"free"`、`"occupied"`、`"reserved"` | `SPACE_STATUSES` |

| 表 | 主要字段 | 约束 |
|---|---|---|
| `users` | id, username, password_hash, role | username 唯一 |
| `residents` | id, name, building, room, phone | |

日期时间在数据库中存 ISO 格式文本（如 `2026-11-16T08:30:00`），读出时转回 `datetime`。

`records` 表中保存的是入场时的车牌和车辆类型的副本，不用外键关联 `vehicles`。原因：未登记的临时车也能入场；车辆资料之后被修改或删除，历史记录仍然准确。详见 ADR-004。

## 五、计费模块的类设计（`app/services/billing.py`）

这是全项目体现"面向对象"的核心：三类车用同一个方法名 `calc`，各自实现不同规则，调用方不需要写 `if 车辆类型 == ...`。

```python
from abc import ABC, abstractmethod
from datetime import date, datetime

class FeePolicy(ABC):
    """计费策略的抽象基类。"""
    @abstractmethod
    def calc(self, enter: datetime, exit: datetime) -> int:
        """返回应收金额（元）。exit 早于 enter 时抛出 ValueError。"""

class HourlyFeePolicy(FeePolicy):
    """按小时计费，带免费时长和每 24 小时封顶。临时车和访客车使用。"""
    def __init__(self, rule: FeeRule): ...
    def calc(self, enter: datetime, exit: datetime) -> int: ...

class MonthlyFeePolicy(FeePolicy):
    """月租车：出场日期不晚于到期日则免费，否则交给 fallback 计费。"""
    def __init__(self, expire: date, fallback: FeePolicy): ...
    def calc(self, enter: datetime, exit: datetime) -> int: ...

def make_policy(vehicle_type: str, monthly_expire: date | None,
                rules: dict[str, FeeRule]) -> FeePolicy:
    """根据车辆类型组装对应的计费策略。"""
```

用到的面向对象概念：抽象类与抽象方法、继承、多态（同一调用，不同行为）、组合（月租策略内部持有一个备用策略）。答辩时可以直接讲这一段。

新增一种车辆类型（例如"业主亲属车"）时，只需新增一个策略类并在 `make_policy` 中登记，出入流程和界面不用改。第 8 天的需求变更演练会验证这一点。

### auth.py（A）

```python
def hash_password(password: str) -> str            # 标准库 hashlib.pbkdf2_hmac，带随机盐
def verify_password(password: str, password_hash: str) -> bool
def can_access(role: str, feature: str) -> bool    # 角色能否使用某功能；未知角色或功能返回 False
def authenticate(user_repo, username: str, password: str) -> User | None   # 登录校验，失败返回 None
def ensure_default_admin(user_repo) -> None        # users 表为空时写入 admin / admin123（只存哈希）
def change_password(user_repo, user_id: int, old_password: str, new_password: str) -> None
    # REQ-002：旧密码错误或新密码少于 6 位时抛 ValueError，数据库不变
```

哈希字符串格式为 `pbkdf2_sha256$迭代次数$盐$哈希`，盐和哈希为十六进制。
用户名不存在和密码错误都返回 `None`，界面统一提示"用户名或密码错误"。
功能编号为 `auth.FEATURE_*` 常量，与侧边栏页面一一对应（gate、record、resident、vehicle、space、
reservation、fee_rule、alert、stats、user、backup）。权限用白名单 `ROLE_FEATURES`：管理员可用全部，
门卫只能用 gate、record、reservation、alert、stats（REQ-020、ADR-007）。
`change_password` 的异常消息：`"旧密码不正确"`、`"新密码不能少于 6 位"`、`"用户不存在"`。

### gate.py（D）

```python
class GateService:
    def __init__(self, record_repo, vehicle_repo, fee_rule_repo): ...
    def enter(self, plate: str, now: datetime, operator: str) -> ParkingRecord
    def exit(self, plate: str, now: datetime, operator: str) -> ParkingRecord
```

`enter` 在车牌已在场时抛出 `ValueError`；`exit` 在找不到在场记录时抛出 `ValueError`。当前时间由界面传入，方便测试时指定任意时间。

`enter` 在车牌格式不正确时也抛出 `ValueError`；`exit` 在出场时间早于入场时间时也抛出 `ValueError`。

### space.py（C）

```python
class SpaceService:
    def __init__(self, space_repo, vehicle_repo=None): ...
    def delete(self, space_id: int) -> None
    def assign_fixed(self, space_id: int, plate: str) -> None    # REQ-007
    def release_fixed(self, space_id: int) -> None               # REQ-007
```

`vehicle_repo` 是可选参数，原有 `SpaceService(space_repo)` 写法不受影响；分配固定车位时需要传入，
车辆只通过 `VehicleRepo.get_by_plate` / `get` 查询。

`delete` 在车位不存在、正被占用、或仍被预约引用时抛出 `ValueError`，页面只负责显示错误信息。

`assign_fixed` 规则不通过时抛出 `ValueError`：`"该车位已不存在，请刷新"`、`"该车牌未登记"`、
`"只有月租车可以分配固定车位"`、`"该车位已绑定其他车辆"`、`"该车辆已有固定车位"`、`"只能分配空闲车位"`。
分配成功后写入 `fixed_vehicle_id`，状态变为 `occupied`；车辆不在场时也保持 `occupied`（ADR-006）。

`release_fixed` 把 `fixed_vehicle_id` 置空、状态变为 `free`；车位不存在时抛出 `"该车位已不存在，请刷新"`，
未绑定车辆时抛出 `"该车位没有绑定车辆"`。

### vehicle.py（B）

```python
class VehicleService:
    def __init__(self, vehicle_repo): ...
    def add(self, obj: Vehicle) -> int
    def update(self, obj: Vehicle) -> None
    def delete(self, vehicle_id: int) -> None
```

REQ-004、REQ-005。写法参照 `ResidentService`：业务判断都在这里，`VehicleRepo` 只做读写，页面的新增、修改、删除都调用本服务，不直接调 repo 的写方法。

`add` 和 `update` 的规则不通过时抛出 `ValueError`：

- 车牌不符合 `is_valid_plate`：`"车牌格式不正确"`（与入场提示一致）
- 车辆类型不在 `VEHICLE_TYPES` 中：`"车辆类型不正确"`
- 月租车没有住户：`"月租车必须绑定住户"`；没有到期日：`"月租车必须填写到期日"`
- 访客车没有被访住户：`"访客车必须填写被访住户"`；临时车的住户可以为空
- 车牌重复：`vehicles.plate` 的 UNIQUE 约束让数据库拒绝写入，服务层捕获 `sqlite3.IntegrityError`，转为 `"该车牌已登记"`

非月租车保存时，`monthly_expire` 一律置为 `None`；页面在类型不是月租时禁用到期日输入。

`delete` 删除仍绑定固定车位的车辆时，`spaces.fixed_vehicle_id` 外键让数据库拒绝删除，服务层捕获 `sqlite3.IntegrityError`，转为 `"请先释放该车辆的固定车位"`。

### repository（各自负责人）

每个 repo 是一个类，构造时接收数据库连接。统一提供：

```python
def add(self, obj) -> int            # 返回新记录的 id
def update(self, obj) -> None
def delete(self, id: int) -> None    # record_repo 不提供
def get(self, id: int)               # 找不到返回 None
def list_all(self) -> list
```

另外按需要提供查询方法，例如 `vehicle_repo.get_by_plate(plate)`、`record_repo.get_present(plate)`、`record_repo.list_between(start, end)`。新增查询方法不算改接口，但要补到本文档。

骨架中已建好的查询方法：

| repo | 方法 | 用途 |
|---|---|---|
| `UserRepo` | `get_by_username(username) -> User \| None` | 登录 |
| `ResidentRepo` | `search(keyword) -> list[Resident]` | 按姓名或楼栋房号模糊查询 |
| `VehicleRepo` | `get_by_plate(plate) -> Vehicle \| None` | 入场时确定车辆类型 |
| `VehicleRepo` | `search(keyword) -> list[Vehicle]` | 按车牌模糊查询，如 `"A123"` 能找到 `豫A12345`（REQ-004，B-2 新增） |
| `VehicleRepo` | `list_by_resident(resident_id) -> list[Vehicle]` | 查某住户名下的车辆（REQ-004，B-2 新增） |
| `SpaceRepo` | `list_by(zone, status) -> list[ParkingSpace]` | 按区域、状态筛选，参数为 `None` 表示不限 |
| `SpaceRepo` | `get_by_fixed_vehicle(vehicle_id) -> ParkingSpace \| None` | 查车辆已绑定的固定车位（REQ-007，C-2 新增） |
| `RecordRepo` | `get_present(plate)`、`list_present()`、`list_between(start, end)` | 在场查询、记录查询；不提供 `delete` |

**例外**：`FeeRuleRepo` 以 `vehicle_type` 为主键，没有 id，也不需要增删，只提供 `get(vehicle_type) -> FeeRule | None`、`list_all()`、`update(rule)`。
`get("monthly")` 返回 `None`（月租车没有收费规则）；`update` 对不存在的车辆类型什么也不改，是否合规由 `services/fee_rule.py` 判断。

`db.py`（A）：

```python
def get_connection(path: str = "data/parking.db") -> sqlite3.Connection
def init_db(conn: sqlite3.Connection) -> None     # 建表，写入默认收费规则
def list_tables(conn: sqlite3.Connection) -> set[str]   # 所有表名，备份还原时校验文件用
```

默认管理员由 `main.py` 在 `init_db` 之后调用 `auth.ensure_default_admin` 写入。
原因：生成密码哈希是业务规则，放在 `services/auth.py`；`repository` 不能反过来导入 `services`。

### 界面页面（各自负责人）

每个页面是一个 `QWidget` 子类，构造时接收它需要的 service 或 repo。页面由组长在 `main_window.py` 中统一注册，页面负责人不改 `main_window.py`。

骨架中每个页面都是只有 `__init__(self, parent=None)` 的占位类，类属性 `TITLE` 是侧边栏显示的名称。负责人给构造函数加参数时，在合并请求中写明需要哪些 repo 或 service，由组长改 `main_window.py` 的 `_build_pages`。

主窗口按 `can_access(当前角色, 功能编号)` 决定创建哪些页面，没有权限的页面不创建、不出现在侧边栏。
新增页面时，组长要同时在 `auth.py` 登记功能编号并决定门卫能否使用；不登记的功能谁都看不到。

登录窗口 `LoginWindow(authenticate)` 接收一个函数 `authenticate(username, password) -> User | None`，自己不验证密码。登录成功时发出 `logged_in(User)` 信号。

## 七、测试约定

- 测试函数名带需求编号：`test_req012_temp_31_minutes_costs_3`。
- 业务规则测试直接构造数据类对象，不碰数据库。
- repository 和 `GateService` 的测试使用 `get_connection(":memory:")`。
- 预期值来自需求清单的验收条件。统计类功能另用手算的小数据集核对。
- 界面不写自动化测试，按需求清单的验收条件手工检查并截图，截图用于实训报告。
