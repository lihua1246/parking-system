# 分工与任务卡

## 一、五人分工

分工原则：按文件划分，任何两个人不同时修改同一个文件。

| 代号 | 角色 | 需求 | 独占的文件 |
|---|---|---|---|
| A | 组长：架构与集成 | REQ-001、002、020、021、023 | `main.py`、`app/models/entities.py`、`services/auth.py`、`services/user.py`、`services/backup.py`、`repository/db.py`、`repository/user_repo.py`、`ui/login_window.py`、`ui/main_window.py`、`ui/pages/user_page.py`、`ui/pages/backup_page.py` |
| B | 住户与车辆 | REQ-003、004、005、025 | `services/validators.py`、`services/alerts.py` 中的 `expiring_monthly`、`repository/resident_repo.py`、`repository/vehicle_repo.py`、`ui/pages/resident_page.py`、`ui/pages/vehicle_page.py` |
| C | 车位与预约 | REQ-006、007、022、028 | `services/reservation.py`、`repository/space_repo.py`、`repository/reservation_repo.py`、`ui/pages/space_page.py`、`ui/pages/reservation_page.py` |
| D | 出入与计费 | REQ-008 至 015、024 | `services/billing.py`、`services/gate.py`、`services/alerts.py` 中的 `overstay`、`repository/record_repo.py`、`repository/fee_rule_repo.py`、`ui/pages/gate_page.py`、`ui/pages/record_page.py`、`ui/pages/fee_rule_page.py`、`ui/pages/alert_page.py` |
| E | 统计与报告 | REQ-016 至 019、026、027 | `services/stats.py`、`services/export.py`、`ui/pages/stats_page.py`；另负责实训报告汇总与排版 |

每个人同时负责自己模块对应的 `tests/` 文件。

**两处共用文件的处理**

- `services/alerts.py` 由 B 和 D 各写一个函数。骨架已把 `overstay`（D）和 `expiring_monthly`（B）两个空壳都建好，各自只改自己的函数体，不碰对方的函数；两人的合并请求谁先合入都可以。
- `ui/pages/alert_page.py` 由 D 负责，展示 B 的到期预警时只调用 B 的函数。

**工作量说明**：D 的需求最多，但计费是纯规则，没有界面负担的部分占一半。A 的需求条数少，另外承担骨架搭建、合并审查和集成。E 的统计依赖 D 的出入记录，前期可以先用手工构造的记录开发和测试，同时开始搭实训报告的框架。

## 二、组长的额外职责

1. 第 1 至 2 天独自完成骨架并合入主分支：目录、数据类、建表、接口空壳、主窗口框架、登录窗口。
   骨架与任务卡 A-1 的分界：骨架只做登录**窗口和跳转**（临时放行 admin / admin123，不查数据库）；
   密码哈希、写入默认管理员、查 users 表校验，以及 A-1 的 4 条验收，全部留给 A-1。
2. 审查每一个合并请求（检查项见协作流程文档）。
3. 每天收工前确认主分支能启动、`pytest` 通过。
4. 维护 `docs/03-架构与接口.md`；接口要变时由组长改文档并通知全员。
5. 把需求清单里的每条需求建成 GitHub Issue，并在清单中更新状态。

## 三、任务卡格式

每个任务一张卡，建成 GitHub Issue。负责人把整张卡交给自己的 AI 助手即可开工。

```markdown
目标：
对应需求：
负责人：
允许修改：
禁止修改：
接口：
规则：
验收：
交付：
```

"规则"和"验收"必须写出具体数值或具体行为。写不出来说明需求还没想清楚，先在组内讨论，不要让 AI 助手自己猜。

### 任务卡 C-2：固定车位分配与释放

```markdown
目标：在车位管理页面上为月租车分配固定车位，并能释放
对应需求：REQ-007
负责人：C
允许修改：app/services/space.py、app/repository/space_repo.py、app/ui/pages/space_page.py、
          tests/test_space_service.py、tests/test_repository_space.py

接口：SpaceService(space_repo, vehicle_repo=None)：新增可选参数，原有 SpaceService(space_repo) 写法不受影响；
      SpaceService.assign_fixed(space_id: int, plate: str) -> None
      SpaceService.release_fixed(space_id: int) -> None
      SpaceRepo 另加 get_by_fixed_vehicle(vehicle_id: int) -> ParkingSpace | None；
      车辆只通过已有的 VehicleRepo.get_by_plate / get 查询
规则：车位不存在时提示"该车位已不存在，请刷新"；
      车牌未登记时提示"该车牌未登记"；不是月租车时提示"只有月租车可以分配固定车位"；

      该车已有固定车位时提示"该车辆已有固定车位"；
      只有状态为 free 的车位能分配，否则提示"只能分配空闲车位"；
      分配成功后车位状态变为 occupied（因此已分配的车位不能删除，沿用 C-1 规则）；
      固定车位在车辆不在场时也保持 occupied，利用率把它计为占用（见 ADR-006）；
      释放后 fixed_vehicle_id 置空、状态变为 free；释放未绑定的车位时提示"该车位没有绑定车辆"；
      页面：选中车位后点"分配固定车位"输入车牌；点"释放"先二次确认；
      列表的"固定车辆"列显示车牌号，不显示车辆 id
验收：（测试中用 SQL 写入车辆，不依赖 B-2）
      1. 月租车 豫A12345 分配到 A-001 后，A-001 的 fixed_vehicle_id 为该车 id，状态为 occupied
      2. A-001 已绑定 豫A12345，再分配 豫B22222 时提示"该车位已绑定其他车辆"
      3. 豫A12345 已绑定 A-001，再分配到 A-002 时提示"该车辆已有固定车位"，A-002 不变
      4. 临时车或访客车分配时提示"只有月租车可以分配固定车位"
```
