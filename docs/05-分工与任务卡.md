# 分工与任务卡

## 一、五人分工

分工原则：按文件划分，任何两个人不同时修改同一个文件。

| 代号 | 角色 | 需求 | 独占的文件 |
|---|---|---|---|
| A | 组长：架构与集成 | REQ-001、002、020、021、023 | `main.py`、`app/models/entities.py`、`services/auth.py`、`services/backup.py`、`repository/db.py`、`repository/user_repo.py`、`ui/login_window.py`、`ui/main_window.py`、`ui/pages/user_page.py`、`ui/pages/backup_page.py` |
| B | 住户与车辆 | REQ-003、004、005、025 | `services/validators.py`、`services/alerts.py` 中的 `expiring_monthly`、`repository/resident_repo.py`、`repository/vehicle_repo.py`、`ui/pages/resident_page.py`、`ui/pages/vehicle_page.py` |
| C | 车位与预约 | REQ-006、007、022、028 | `services/reservation.py`、`repository/space_repo.py`、`repository/reservation_repo.py`、`ui/pages/space_page.py`、`ui/pages/reservation_page.py` |
| D | 出入与计费 | REQ-008 至 015、024 | `services/billing.py`、`services/gate.py`、`services/alerts.py` 中的 `overstay`、`repository/record_repo.py`、`repository/fee_rule_repo.py`、`ui/pages/gate_page.py`、`ui/pages/record_page.py`、`ui/pages/fee_rule_page.py`、`ui/pages/alert_page.py` |
| E | 统计与报告 | REQ-016 至 019、026、027 | `services/stats.py`、`services/export.py`、`ui/pages/stats_page.py`；另负责实训报告汇总与排版 |

每个人同时负责自己模块对应的 `tests/` 文件。

**两处共用文件的处理**

- `services/alerts.py` 由 B 和 D 各写一个函数。由 D 先建文件并合入，B 之后再加自己的函数，避免同时修改。
- `ui/pages/alert_page.py` 由 D 负责，展示 B 的到期预警时只调用 B 的函数。

**工作量说明**：D 的需求最多，但计费是纯规则，没有界面负担的部分占一半。A 的需求条数少，另外承担骨架搭建、合并审查和集成。E 的统计依赖 D 的出入记录，前期可以先用手工构造的记录开发和测试，同时开始搭实训报告的框架。

## 二、组长的额外职责

1. 第 1 至 2 天独自完成骨架并合入主分支：目录、数据类、建表、接口空壳、主窗口框架、登录。
2. 审查每一个合并请求（检查项见协作流程文档）。
3. 每天收工前确认主分支能启动、`pytest` 通过。
4. 维护 `docs/03-架构与接口.md`；接口要变时由组长改文档并通知全员。
5. 把需求清单里的每条需求建成 GitHub Issue，并在清单中更新状态。

## 三、任务卡格式

每个任务一张卡，建成 GitHub Issue。负责人把整张卡交给自己的 AI 助手即可开工。

```markdown
目标：
对应需求：
负责人：
允许修改：
禁止修改：
接口：
规则：
验收：
交付：
```

"规则"和"验收"必须写出具体数值或具体行为。写不出来说明需求还没想清楚，先在组内讨论，不要让 AI 助手自己猜。

## 四、首批任务卡

骨架合入主分支后（预计第 2 天结束）发放。每人一张，全部属于基础功能。

### 任务卡 A-1：登录与主窗口

```markdown
目标：用户能登录并进入带侧边导航的主窗口
对应需求：REQ-001
负责人：A
允许修改：app/services/auth.py、app/repository/user_repo.py、app/ui/login_window.py、
          app/ui/main_window.py、tests/test_auth.py
禁止修改：其他人的页面文件
接口：hash_password、verify_password（见架构文档第六节）
规则：密码用 hashlib.pbkdf2_hmac 加随机盐保存；登录失败统一提示"用户名或密码错误"，
      不区分是用户名错还是密码错
验收：1. 默认账号 admin / admin123 可以登录
      2. 密码错误时停留在登录窗口并显示提示
      3. 数据库 users 表中查不到明文 "admin123"
      4. 同一密码两次哈希的结果不同，但都能验证通过
交付：一个合并请求，附 pytest 结果和登录界面截图
```

### 任务卡 B-1：住户管理

```markdown
目标：在界面上完成住户的新增、修改、删除、查询
对应需求：REQ-003
负责人：B
允许修改：app/repository/resident_repo.py、app/ui/pages/resident_page.py、
          app/services/validators.py（仅 is_valid_phone）、
          tests/test_repository_resident.py、tests/test_validators.py

      删除住户前检查其名下是否有车辆，有则拒绝
验收：1. 新增后在列表中能看到，重启程序后仍在
      2. 搜索"张"能找到姓名含"张"的住户，搜索"3号楼"能找到该楼栋的住户
      3. 手机号 1380000000（10 位）被拒绝并提示
      4. 名下有车辆的住户删除时提示"请先删除或转移该住户名下的车辆"
交付：一个合并请求，附 pytest 结果和页面截图
```

### 任务卡 D-1：入场与出场（不含计费）

```markdown
目标：完成车辆入场、出场登记和在场车辆列表，费用暂时固定为 0
对应需求：REQ-008、REQ-009、REQ-010
负责人：D
允许修改：app/services/gate.py、app/repository/record_repo.py、
          app/ui/pages/gate_page.py、tests/test_gate.py
禁止修改：app/models/、main_window.py、其他人的文件
接口：GateService.enter / exit / list_present（见架构文档第六节）
规则：入场时查车辆表确定车辆类型，查不到按临时车；车辆类型写入记录后不再变化；
      同一车牌有未出场记录时不能再次入场；当前时间由界面传入
验收：1. 未登记车牌 豫A12345 入场后，记录的车辆类型为 temp
      2. 同一车牌未出场时再次入场，抛出 ValueError，界面提示"该车辆已在场内"
      3. 出场后记录的 exit_time 不为空，在场列表中不再出现该车
      4. 不在场的车牌出场，抛出 ValueError，界面提示"未找到在场记录"
      5. 入场 08:00、出场 10:15，界面显示停车时长"2 小时 15 分"
交付：一个合并请求，附 pytest 结果和页面截图
说明：这张卡是 MVP 的主干。计费在下一张卡 D-2（REQ-012）中接入。
```

### 任务卡 E-1：车流量与收入统计（规则部分）

```markdown
目标：实现统计函数并用手算数据验证，暂不做界面
对应需求：REQ-016、REQ-017、REQ-018
负责人：E
允许修改：app/services/stats.py、tests/test_stats.py
禁止修改：其他所有文件
接口：daily_flow、monthly_flow、income_by_day、utilization（见架构文档第六节）
规则：入场数按 enter_time 的日期统计；出场数和收入按 exit_time 的日期统计；
      仍在场的记录（exit_time 为空）只计入场，不计出场和收入；
      没有车位时利用率为 0.0
验收：先在测试文件中手工构造 10 条记录（跨 3 天，其中 2 条未出场），
      在注释里写出手算结果，再断言：
      1. 每天的入场数、出场数与手算一致
      2. 每天收入与手算一致，三天合计等于 8 条已出场记录的金额之和
      3. 10 个车位中 4 个 occupied 时利用率为 0.4
      4. 空列表传入各函数不报错
交付：一个合并请求，附 pytest 结果
说明：这些函数只接收列表，不访问数据库，所以不必等其他人完成。
      界面和图表在下一张卡 E-2 中完成。
```
